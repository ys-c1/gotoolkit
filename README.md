# gotoolkit

分层的灰度图编解码工具，用于出题基线。

- `api/` 唯一对外入口，`Options` 是可配参数的公共声明处
- `internal/codec/` 三个格式实现，外部不可引用
- `cmd/gtk/` 命令行，`encode` 与 `decode` 两条子命令
- `testdata/golden/` 三种格式的基准字节，由 `ref/` 生成，**不许改**
- `ref/` 独立参照，只用来生成基准

```
make test
make build
./build/gtk encode --format bmp --in a.pgm --out a.bmp
./build/gtk decode --format bmp --in a.bmp --out b.pgm
```

## 画质阈值选格式（bench / compare）

三种格式默认都是无损的，体积差异只来自容器：PGM ≈ `w·h+头`、BMP ≈ `3w·h+头`、
RLE = `8+2×游程块数`。要在“画质差不多”的前提下比体积，先统一做均匀量化，
再用**真实编码字节**对账，并出图逐像素核对。

画质阈值 τ 定义为“允许的最大逐像素绝对灰度误差”（0..255）。量化器为右移 `s`
位 + 中点反量化，有效位深 `b=8-s`，其最坏误差有闭式上界：

```
E(0)=0；E(s)=2^(s-1) (s>=1)
反解最粗合格档：s*(τ)=0 (τ=0)，否则 min(7, floor(log2 τ)+1)，b*=8-s*
```

`bench` 内置五档固定画幅 `16² / 32² / 64² / 128² / 256²` 和确定性样本
`ramp-shapes-v1`（渐变+圆+矩形+16 级灰阶条，无随机源，含纯 0 像素，因此实测
最大误差严格等于上界）。每档对三种格式各跑 `s=0..7` 全档真实编码→解码→逐像素
比较，选出“实测误差 ≤ τ 且字节数最小”的格式，并把原图、三种格式的码流、解码
PGM/PNG、放大 16 倍的差异图写到 `--out`（默认 `artifacts/bench/`）。

```
make bench                                  # = gtk bench，默认阈值对 4,7
./build/gtk bench --threshold 4             # 只跑一个阈值
./build/gtk bench --thresholds 4,8          # 任意两个阈值 + 一致性对照
./build/gtk bench --in mine.pgm --threshold 10
```

**不指定阈值时行为与现在完全一致**：`encode/decode` 不加 `--threshold` 时不做
量化，三种格式输出与 `testdata/golden/` 逐字节相同（有测试守护）；`bench` 是
新增子命令，不影响原有两条子命令。

### 默认两跑：τ=4 与 τ=7（结论严格一致）

`τ=4` 与 `τ=7` 落在同一个离散误差区间 `[4,7]`，都反解到 `s*=3 / b=5 / E=4`，
所以两次运行的码流逐字节相同，五档的“选中格式 + 体积”对也完全一致：

| 档位 | 画幅 | pgm | bmp | rle | 选中（格式=体积） |
|---|---|---:|---:|---:|---|
| 档1 | 16×16 | 269 | 822 | 430 | **pgm=269B** |
| 档2 | 32×32 | 1037 | 3126 | 940 | **rle=940B** |
| 档3 | 64×64 | 4109 | 12342 | 1962 | **rle=1962B** |
| 档4 | 128×128 | 16399 | 49206 | 3966 | **rle=3966B** |
| 档5 | 256×256 | 65551 | 196662 | 8018 | **rle=8018B** |

结论：最小的 16×16 档 RLE 的 8 字节头 + 每块 2 字节开销使其略大于裸 PGM，选
**pgm**；32×32 及以上平坦/渐变内容上游程收益超过开销，均选 **rle**；BMP 三通道
同值存储始终最大。跨到相邻离散档 `τ=8`（b=4）时五档选中格式仍是
`pgm,rle,rle,rle,rle`，只是 rle 体积降到 `290/588/1200/2406/4858B`；放宽到
`τ=16` 后连 16×16 也变为 rle（194B）。完整机器可读结果见
`artifacts/bench/report.json`，文字报告见 `artifacts/bench/report.txt`。

代码分层：推导与扫描引擎在 `internal/quality/`（外部不可引用），对外类型与函数
经 `api/quality.go` 挂到唯一入口 `package api`，CLI 只依赖 `api`。
