# 灰度三通道展开与亮度守恒

把 8 位灰度图存成 24 位 BMP 时，旧实现让 R=G=B=灰度。这是零误差的，
但三个通道完全冗余。这里给出一条可选的展开路径：三个通道取值不同，
而按亮度公式收回来仍等于原灰度（g≤194 严格相等；g>194 因 G 通道
撞 255 截断而有偏，原因见第 5 节）。

原灰度路径不受影响：不传 `LumaExpand` 时 `Encode`/`Decode` 的字节与
`testdata/golden` 逐字节一致，`TestGrayPathUnchanged` 锁住这一点。

## 1. 参数与开关

- `api.Options.LumaExpand bool`，默认 `false`；只对 `Format=="bmp"` 生效，
  对 pgm/rle 传 true 报 `ErrBadOption`。
- 编码结果在 BMP 头的 `biReserved`（偏移 6..9）写入 `"LUM1"`；头长度仍是
  54 字节，总长不变。解码按标记自动分派：带标记走展开解码，不带标记走原
  灰度解码，调用方不需要传对参数。
- 命令行：`gtk encode --format bmp --luma-expand ...`。

## 2. 亮度定义与守恒等式

亮度权重取 Rec.601 的千分值：

```
Y = (299·R + 587·G + 114·B) / 1000
```

记 `w = (0.299, 0.587, 0.114)`，`Σ w_c = 1`。展开要求：灰度 g 展开成
`q = (q_R, q_G, q_B)` 后，按同一权重收回仍为 g：

```
Σ_c w_c · k_c = 1        （k_c 是展开系数，q_c = g·k_c）
```

这是一条等式、三个未知数，解不唯一。再加「系数向量范数最小」：

```
min ‖k‖²   s.t.  Σ_c w_c·k_c = 1
```

线性约束下的最小范数解唯一，即

```
k_c = w_c / Σ_j w_j²
```

这里 `Σ_j w_j² = 0.299² + 0.587² + 0.114² = 0.446966`。

> 为什么不选「离中性灰最近」：`k=(1,1,1)` 也满足守恒（因为 `Σw=1`），
> 它正是旧的三通道同值方案，误差为 0 但三通道没有区别。最小范数解
> 才真正把三个通道分开。

## 3. 系数（可复算）

千分制整数写法，分母统一为 `Σ Luma_j² = 446966`：

| 通道 | 分子 | 分母 | 值 |
|---|---:|---:|---:|
| R | 299000 | 446966 | 0.668955 |
| G | 587000 | 446966 | 1.313299 |
| B | 114000 | 446966 | 0.255053 |

复算步骤（不用本仓库任何代码）：

1. 取 `Luma = (299, 587, 114)`，令 `D = 299² + 587² + 114² = 446966`；
2. 每个通道的系数是 `1000 · Luma_c / D`；
3. 展开：`q_c = round(g · 1000 · Luma_c / D)`（四舍五入、半数向上），
   再截到 `[0, 255]`；
4. 收回：`ĝ = round((299·q_R + 587·q_G + 114·q_B) / 1000)`。

`round` 一律是整数四舍五入：`round(n/d) = (2n + d) / (2d)`（整除，n,d≥0）。
`api.LumaCoefficients()` 返回的就是第 3 步要用的分子分母。

守恒校验（有理数意义，精确）：

```
299·299000 + 587·587000 + 114·114000 = 446966000 = 1000·446966
⇒ Σ_c w_c·k_c = 1
```

## 4. 往返误差上界（按像素）

展开时每个通道有两类误差：舍入 `|e_c| ≤ 1/2`；截断到 255 时误差为
`−d_c`，`d_c = max(0, g·k_c − 255)`。收回再取整添 `±1/2`。逐项相加：

```
|e| ≤ 1/2 + Σ_c w_c · max(1/2, d_c)
```

`expand.Bound(g)` 用整数精确算 `floor(上式)`。对 0..255 全枚举：每一级
都不越界，且 `g=255` 取到 47，所以这个上界既是上界也是紧的（不能更小）。

只有 G 会截断：`k_G = 1.313299 > 1`，`255/k_G = 194.16`，故 `g ≤ 194`
时三通道都不截断。在 0..194 内展开再收回是**恒等**（实测算术结果为 0），
这段区间的上界 1 只是舍入链的最坏情形，实际取不到。

## 5. 三档灰度实测

把 0..255 分三档：0–85、86–170、171–255。档内上界取逐级 `Bound(g)` 的
最大值。样本是 17×16 = 272 像素，按行铺 0..255，0..15 各出现两次、其余一次，
可由 `go run ./cmd/lumareport` 复现。

| 档 | 区间 | 样本 | 误差上界 | 实测最大误差 | \|误差\|>1 的级数 |
|---:|---|---:|---:|---:|---:|
| 1 | 0–85 | 102 | 1 | 0 | 0 |
| 2 | 86–170 | 85 | 1 | 0 | 0 |
| 3 | 171–255 | 85 | 47 | 47（g=255） | 59（197–255） |

三档误差上界分别是 **1 / 1 / 47 级**。第三档的 47 全部来自 G 截断：
`d_G(255) = 255·1.313299 − 255 = 79.89`，乘权重 0.587 ≈ 46.9，加上舍入
即为 47。

195、196 两级误差恰为 1 级（不超限），197–255 共 59 级超过 1 级。
完整逐像素清单见第 7 节与 `artifacts/luma/report.txt`。

## 6. 亮度守恒的三组实测

展开后存进 BMP 的 RGB 记为 `q`，收回得 `ŷ = round(Σ w_c·q_c)`。
守恒式逐像素成立 `ŷ = g` 当且仅当无截断；截断时

```
Σ_pix ŷ = Σ_pix g − Σ_pix (w_G·d_G)    （再叠加取整的 ±1 逐像素）
```

`go run ./cmd/lumareport` 的实测（整数千分权重精确累加）：

| 组 | 区间 | 像素 | Σg | Σround(Y) | ΣY−Σg | 最大单像素差 |
|---:|---|---:|---:|---:|---:|---:|
| 1 | 0–85 | 102 | 3775 | 3775 | 0 | 0 |
| 2 | 86–170 | 85 | 10880 | 10880 | 0 | 0 |
| 3 | 171–255 | 85 | 18105 | 16655 | −1450 | 47 |
| 全 | 0–255 | 272 | 32760 | 31310 | −1450 | 47 |

前两组 `Σround(Y) = Σg` 精确相等；第三组的 −1450 全部由第三档内 G 通道
在 195–255 上被截断造成（171–194 仍恒等）。注意「全部由第三档贡献」不等于
「整档都截断」，171–194 这段是干净的。

「逐级覆盖」的独立复算（每级恰一个像素）见下；它与上表的差只出现在第一档：
272 像素的样本里 0..15 各重复一次，全部落在第一档，故第一档 Σg 多出
0+1+…+15 = 120：

| 区间 | Σg | Σround(Y) | ΣY−Σg |
|---|---:|---:|---:|
| 0–85 | 3655 | 3655 | 0 |
| 86–170 | 10880 | 10880 | 0 |
| 171–255 | 18105 | 16655 | −1450 |
| 0–255 | 32640 | 31190 | −1450 |

两表差额 −1450 完全一致，与是否重复样本无关，只由 195–255 这 61 个灰度决定。

## 7. 超限像素与成因

判定口径：`|ŷ − g| > 1`。样本里共 59 个，坐标、灰度、展开的 RGB、截断
通道、收回值、误差、单像素上界都在报告里逐行列出，例如：

| 坐标 | 灰度 | R,G,B | 截断 | 收回 | 误差 | 上界 |
|---|---|---|---:|---:|---:|
| (10,11) | 197 | 132,255,50 | G | 195 | −2 | 2 |
| (3,13) | 224 | 150,255,57 | G | 201 | −23 | 23 |
| (0,15) | 255 | 171,255,65 | G | 208 | −47 | 47 |

成因：`k_G > 1`，G 在 `g > 194` 时越过 255 被截断。截断量 `d_G` 乘权重
0.587 后被收回，故误差约 `−0.587·d_G`，再叠 `±0.5` 舍入。R、B 的系数都
小于 1，永远不会截断，所以超限只出现在 G 一路、且只在第三档。

单像素上界一列按 `Bound(g)` 逐像素给出，实测误差均不越界；它比整档上界
更贴，判定不因相邻灰度而被放大。

## 8. 熵（比特每像素）

按符号出现次数算经验熵：

```
H = −Σ_i (n_i/N) · log2(n_i/N)
```

样本是像素，所以单位就是**比特每像素**。`api.EntropyBitPerPixel` 是同一个
式子。17×16 样本上：

| 通道 | 不同符号数 | H (bit/pixel) |
|---|---:|---:|
| 灰度样本 | 256 | 7.969816 |
| 展开 R | 172 | 7.315404 |
| 展开 G | 195 | 6.612609 |
| 展开 B | 66 | 6.013790 |

灰度样本 272 个像素覆盖 256 个符号（16 个出现两次），故略低于
`log2(256)=8`。三通道熵不等：R 的步长 0.669 级，接近一一对应；B 的步长
0.255 级，256 级压到 66 个取值，重复多、熵最低；G 的步长 1.313 级、取值
最密（195 个），但 195–255 共 61 级全压在 255 上（重复 62 次），所以 G 的
熵反而低于 R。

## 9. 头部开销

同一画幅 17×16（N=272），两种格式的实际总长：

| 格式 | 头字节 | 额外字节（相对 N 个样本） | 实际总长 |
|---|---:|---:|---:|
| pgm | 13 | 13 | 285 |
| bmp(灰度) | 54 | 614 | 886 |
| bmp(展开) | 54 | 614 | 886 |

- PGM 头是文本 `P5\n17 16\n255\n`，13 字节，无对齐。
- BMP 头 54 字节；每行 `3·17=51` 字节补到 52，补齐 `1·16=16` 字节；
  第二三通道多 `2N=544` 字节。额外 = 54 + 16 + 544 = 614。
- 差值 BMP−PGM = (54−13) + 16 + 544 = **601 字节**；实测 886−285 = 601。
- 展开与不展开的 BMP 总长相同（886 字节）：差值来自格式本身（头 + 行对齐 +
  三通道），与是否展开无关。展开只改像素字节，不增字节数。
