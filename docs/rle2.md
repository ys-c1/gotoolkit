# GTR2 块级自适应游程编码

针对 GTR1 的痛点：长渐变里每个游程长度为 1，固定 `(计数,值)` 两字节反而把
数据膨胀到约 2 倍。GTR2 把像素切成块，**每块按自身符号熵独立决定游程上限
与是否转义**，并对“分块不够细”的块递归二分。

GTR1（`rle` 格式、golden 字节）保持不动；GTR2 是新格式 `rle2`，魔数 `GTR2`。

## 1. 字节格式

主头 9 字节：

| 偏移 | 长度 | 含义 |
|---|---|---|
| 0..3 | 4 | 魔数 `GTR2` |
| 4..5 | 2 | 宽，uint16 LE |
| 6..7 | 2 | 高，uint16 LE |
| 8 | 1 | 基准块长（编码端固定 255，合法区间 64..255） |

每个块 2 字节块头 + 变长负载：

| 字节 | 含义 |
|---|---|
| byte0 | `0x00` = 转义块（负载为原始字节）；`1..255` = 游程块，该值即游程上限 `cap` |
| byte1 | 块像素长度 - 1（块长 1..255） |

- 游程块负载：若干 `(计数, 值)`，计数 `1..cap`，块内计数之和 = 块长。
- 转义块负载：块长个原始字节。
- 解码端按块顺序扫描：转义块直接拷 `块长` 字节；游程块按游程对扫描，累计
  计数达到块长即定位下一块（游程负载变长，不能按块长跳字节）。

`byte0` 用 0 而非一个独立标志位表示转义：游程 `cap` 最小为 1，0 天然空闲，
避免了“cap=255 点亮最高位被误判成转义”的冲突。

基准块长取 **255** 而非 256：GTR1 的游程上限就是 255，块边界与 GTR1 的天然
游程切点对齐，tier 1（cap 钳在 255）下游程块发出的 `(计数,值)` 才能与 GTR1
对同段像素的输出逐字节一致。

## 2. 每块编码决策

```
H = 块的香农熵（比特/像素）
若 转义条件命中            -> 转义块（原始字节）
否则 cap = clamp(round(K/H), 1, 255)，按 cap 切游程
若 游程块且 2*游程数 > 1.10 * ceil(H*块长/8) 且 块长 > 64
                           -> 递归二分后各自编码
```

### 2.1 游程上限反解：`cap = round(K / H)`

每像素香农熵 H 越低，游程越长，应允许越大的计数上限；二者成反比，故取
`cap = K/H`，再钳到 `[1,255]`。常值块 H=0 无不确定性，直接给 cap=255。

**三档亮度系数 K（量纲：比特）：**

| 档 | K | 取向 |
|---|---|---|
| 1 | 2040 | 宽松：H≥8 才会让 cap 降到 255 以下，常规块基本钳在 255，行为最接近 GTR1 |
| 2 | 512 | 中等：H≈2 起 cap 开始明显低于 255 |
| 3 | 128 | 收紧：H≈0.5 起就限制游程长度，长游程被切成更多对 |

K 的“亮度”命名依据：它与摄影曝光系数同构——曝光量 = 入射光 × 增益系数，
这里 `游程上限 = 系数 K ÷ 符号熵 H`，K 是把“每像素比特数”换算成“该熵水平下
值得允许的游程长度”的比例常数，量纲是比特。K 越大，同等熵下放行的游程越长。

### 2.2 反算验证（系数可由已知输入反推）

对任一**未触发钳位**的 cap，给定 cap 反解 `H = K/cap`，再正算 `rle2Cap(K,H)`
必须回到同一个 cap。测试 `TestRLE2CapInverse` 对三档各自的未钳位区间逐值
验证（K=2040 覆盖 cap 10..255；K=512 覆盖 2..255；K=128 覆盖 1..128），
并验证 H=0 / 极小熵钳到 255、极大熵钳到 1 两个边界。

## 3. 转义块：触发条件与统计

满足任一条件即转义为原始字节（1 字节/像素）：

1. **熵阈值**：`H >= 4.0` 比特/像素。
   依据 iid 符号源平均游程长度 `E[L] = 1/(1-Σp²)`，而碰撞熵
   `H2 = -log2(Σp²)`，故 `E[L] = 1/(1-2^-H2)`。H2=4.0 时
   `E[L] = 1/(1-1/16) = 1.0667`，平均游程已接近长度 1，两字节游程对相对
   一字节原始值接近翻倍，游程编码注定不划算。
2. **实测膨胀**：`2 * 游程数 > 块长`（游程对负载已超过原始字节数）。
   块长 ≤ 2 时豁免——一个游程对最多 2 字节，与原始字节同价，谈不上膨胀
   （避免 1 像素尾块被误判转义）。

转义块**不参与递归二分**：它的负载就是原始字节，对熵下界的比值恒在 1.0
附近（仅 ceil 取整），不存在“分块不够细”，再切只会白花块头。

每条 bench 报告单列 `转义=N` 块数及其触发来源；高熵图（noise）满块全部
转义，长渐变（ramp）几乎全部转义，常值图零转义。

## 4. 一成判据与递归二分

块的香农熵下界（仅负载，字节）：`bound = ceil(H * 块长 / 8)`。

游程块若预估负载 `2*游程数` 超过下界的 1.10 倍，且块长仍 > 64，则二分后
各自递归。64 是下限：再细的块，2 字节块头相对负载的占比会吃掉收益。

- 判据只作用于游程块；转义块直接接受（见上）。
- `WorstRatio` 记录所有末块中最大的 `实际负载 / 熵下界`。
- 若某数据在末块达到 64 像素下限后 WorstRatio 仍 > 1.10，这是 **RLE 对该
  数据的固有低效**（游程对的两字节结构性开销），不是分块不够细——再分也
  无法突破，报告中明确标注。

## 5. 当前参数下的体积对照（256×256 = 65536 像素）

由 `go run ./cmd/rle2bench` 生成。每档给**体积**与**熵下界**两个数（下界为
逐块香农熵求和，字节；体积为含 9 字节主头的完整流长度）。

| 图 | GTR1 体积 | 档 | 体积 | 熵下界 | 转义块 | 游程块 | 二分 |
|---|---|---|---|---|---|---|---|
| 常值 flat | 524 | 1/2/3 | 1041 | 0 | 0 | 258 | 0 |
| 长渐变 ramp | 131080 | 1/2/3 | 66062 | 65535 | 257 | 1 | 0 |
| 中纹理 texture | 16392 | 1/2/3 | 17359 | 32896 | 0 | 258 | 0 |
| 长游程 longrun | 984 | 1 | 2003 | 9814 | 0 | 258 | 0 |
| 长游程 longrun | 984 | 2 | 2003 | 9814 | 0 | 258 | 0 |
| 长游程 longrun | 984 | 3 | 2601 | 9814 | 0 | 258 | 0 |
| 高熵 noise | 130576 | 1/2/3 | 66062 | 58899 | 257 | 1 | 0 |
| 混合 mixed | 87518 | 1/2/3 | 44557 | 41539 | 172 | 86 | 0 |

要点：

- **长渐变**：GTR1 131080（膨胀到 2×），GTR2 66062，仅比原始像素多 526
  字节（块头），相对熵下界差距 0.8%，远在一成以内。
- **高熵**：GTR2 66062 vs GTR1 130576，转义使体积回到 1 字节/像素量级；
  相对逐块下界差距约 12%，超一成，原因是末块已到 64 像素下限、且转义块的
  块头是结构性开销——属 RLE 固有低效，非分块不细。
- **三档差异只在“块内存在超过该档 cap 的连续游程”时显现**：长游程图上
  tier 3 因 cap 收紧把长游程切成更多对（2601 > 2003）；自然游程普遍短于
  所有档 cap 时三档体积相同，这是正确行为而非缺陷。
- **与 GTR1 的逐字节关系**：块边界恰为游程切点时（常值、游程整除块长），
  tier 1 游程块的 `(计数,值)` 与 GTR1 同段输出逐字节相同（测试
  `TestRLE2Tier1PairsMatchGTR1Aligned`）；混合数据上固定 255 块边界不保证
  落在游程切点，跨界游程会多切一对，这是分块格式的固有代价。

## 6. 用法

```
make test
go run ./cmd/rle2bench                       # 三档体积/下界/转义/一成判据
./build/gtk encode --format rle2 --tier 1 --in a.pgm --out a.gtr2
./build/gtk decode --format rle2 --tier 1 --in a.gtr2 --out b.pgm
```

代码入口：`internal/codec/rle2.go`（编解码与全部决策）、
`api/api.go`（`EncodeRLE2WithStats` 返回分块统计）、
`cmd/rle2bench/main.go`（复算与报告）。
