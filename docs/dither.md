# 调色板与抖动的配比

调色板（桶数 `L`）负责把 0..255 压到 `L` 级，代价是**色块**；有序抖动负责把
色块打散，代价是**噪声**。两者都在增加误差，关键是把总误差拆成可比较的两部分，
再按配比选一个使加权和最小的抖动强度。实现见 `internal/quant`，公开入口见
`api.OptimalDither` 与 `api.Options.{Levels,Dither,AutoDither}`。

## 1. 误差怎么拆

调色板取 `L` 级等距，间距 `q = 255/(L-1)`，`k` 号桶的量化值
`p_k = round(k·q)`。抖动强度 `τ∈[0,1]`，像素 `(x,y)` 的阈值偏移为

```
d(x,y) = ((Bayer[y&7][x&7] + 0.5)/64 − 0.5) · τ        （d ∈ (−τ/2, τ/2)）
out = p[clamp(round(v/q + d))]
```

τ=0 时抖动项消失，退化为纯色块量化；τ=1 时偏移铺满一个量化步长。

把**同一个输入灰度值 v** 的像素看作一组；它们在 8×8 Bayer 的 64 个相位上输出
不同，记

```
μ_v(τ) = 该组输出均值        σ_v²(τ) = 该组输出方差
p_v    = 灰度为 v 的像素占比
```

于是

```
色块误差  B = Σ_v p_v · (μ_v(τ) − v)²      整片同灰度区域被系统搬移多少
噪声误差  N = Σ_v p_v · σ_v²(τ)            同灰度区域内部被打散出多少起伏
```

**量纲统一**：由全方差公式，对每个 v 都有
`E[(out−v)²] = (μ_v−v)² + σ_v²`，所以

```
B + N = Σ_v p_v · E[(out−v)²] = 逐像素均方误差 MSE
```

两部分都是“灰度级²/像素”，可以直接相加，加权时不会因为一边是均值平方、一边是
方差而失真。这条恒等式由测试 `TestDecompositionIsMSE` 直接验证。

> 为什么不按调色板“桶”分组：桶的边界随 `L` 改变，桶内均值误差还混入了
> “像素值离桶中心有多远”这一项，`B+N` 就不再等于 MSE，两部分失去了共同基准。
> 按输入灰度分组后，`B+N=MSE` 成为硬性约束，权重才是干净的取舍。

## 2. 权重怎么取

```
W = 4·B + 1·N
```

依据是两类伪影的**视觉可积性**不同，而不是随便拍一个数字：

- 色块（B）是低频、空间相干的：一条色带会跨很多像素连成轮廓，缩小、拉远观看
  都不会被平均掉，它在观看条件下的可见度基本不打折。
- 抖动噪声（N）是高频、逐像素近似独立的（Bayer 矩阵保证了这一点）：视觉系统
  在约 2×2 的邻域内积分时，独立噪声的功率按面积被摊薄，4 个像素平均使方差降为
  1/4。因此相同均方能量下，噪声的主观可见度约为色块的 1/4。

即“同能量下色块可见度约为噪声的 4 倍”，取 4:1。这不是一个敏感的选择：

在连续近似（忽略调色板取整与端点裁剪）下可以解析地算出

```
B = q²·(1−τ)²/12          N = q²·τ/6
```

（对连续模型做数值积分，相对误差 <1e-9；离散模型因调色板取整会有小幅偏差，
正如下文表格中 L=4 与 L=64 的 τ* 并不完全相等）。记 `q²` 为共同因子，则

```
W(τ) = r·q²·(1−τ)²/12 + q²·τ/6,      r = W_banding / W_noise
dW/dτ = q²·[−r(1−τ)/6 + 1/6] = 0  ⇒  τ* = 1 − 1/r
```

`r=4` 时 `τ*=0.75`；`r=1` 时 `τ*=0`，正是“权重比不高于 1 就不值得抖动”的
分界。下图是不同权重比下**离散模型**（含调色板取整与端点裁剪）给出的最优 τ
（三档桶数），与闭式解一致：

| 权重比 r | L=4 | L=16 | L=64 |
|---|---|---|---|
| 1.10 | 9% | 9% | 27% |
| 1.25 | 20% | 20% | 29% |
| 2 | 50% | 50% | 44% |
| 3 | 67% | 67% | 68% |
| **4** | **73%** | **73%** | **79%** |
| 6 | 83% | 83% | 85% |
| 8 | 88% | 87% | 87% |

- `r ≤ 1` 时最优解退化为 τ=0：抖动必然抬高总 MSE，色块若几乎不计权重就没有
  理由引入噪声。因此 `r` 必须明显大于 1，但 `r≥1.1` 就足以开出内点解。
- `r` 从 2 到 8，最优 τ 都在 0.44–0.88 之间连续变化，4:1 落在平台中部。
  用 4:1 的 W 评价，若把权重误取成 3:1 或 6:1，W 只差 1.4–3.4%；误取成 2:1
  或 8:1 才差到 3–19%。即结论对权重比在 3–8 内不敏感。
- 4:1 与“2×2 视觉积分摊薄 4 倍”的物理图像一致，是有依据的取值而非拟合结果。

结论：权重比取 4:1。它既让内点解存在，又位于参数不敏感的平台中央。

## 3. 三档桶数的最优配比

搜索目标：均匀灰度先验（`UniformHist`）下使 `W = 4B + N` 最小的 τ；τ 的搜索
精度 5e-5，同分取较小 τ。表格数值由 `api.OptimalDither(L)` 给出并经
`TestOptimizeBeatsBothExtremes` 校验。

| 桶数 L | 步长 q | 最优强度 τ* | 色块 B | 噪声 N | 最优 W | 不抖动 W | 满抖动 W |
|---|---|---|---|---|---|---|---|
| 4 | 85.00 | 73% | 42.1394 | 881.7375 | **1050.2953** | 2398.5938 | 1204.7477 |
| 16 | 17.00 | 73% | 1.6843 | 35.2645 | **42.0018** | 95.6250 | 48.0790 |
| 64 | 4.05 | 79% | 0.1270 | 2.1537 | **2.6618** | 6.0938 | 3.0442 |

三档桶数下最优 W 都同时低于两种极端：相对不抖动降低约 56%，相对满强度抖动
降低约 12%。桶数越多，最优 τ 略高——`q` 变小时每个灰度的误差能量更小，用
噪声换色块的性价比更高。

**验证**：当图中每个灰度都均匀覆盖 Bayer 全部 64 个相位时，模型 `Predict`
与逐像素 `Measure` 完全一致（误差 <1e-9，`TestPredictMatchesMeasurementOnTiles`），
说明建模与实现没有脱节。对不满足该条件的平滑图像（正弦夹具，256×256），三种桶数
下逐个整数百分比实测搜索：

| L | 实测 τ=0 | 模型 τ* 下的实测 W | 实测最优 τ | 实测最优 W | 实测 τ=1 |
|---|---|---|---|---|---|
| 4 | 2333.302 | 1046.005 | 73% | 1046.005 | 1209.944 |
| 16 | 94.530 | 41.784 | 76% | 41.778 | 48.169 |
| 64 | 6.088 | 2.680 | 79% | 2.680 | 3.054 |

模型最优点的实测 W 与实测最优相差 <0.02%，最优 τ 落在实测平台的 3 个百分点内。
（`TestSmoothImageOptimumMatchesModel` 用 2% 带宽和 4 个百分点容差校验。）

## 4. 不启用时产物不变

`Levels=0`（默认）时 `prepare` 完全不进入量化分支，`Encode` 的字节流与历史版本
逐字节一致。`TestGoldenBytes` 与 `TestQuantizationDisabledKeepsOutput` 分别用
golden 基准和“设了但为零”的参数组合把这一点钉住。

## 5. 用法

```go
plan, _ := api.OptimalDither(16)        // {Levels:16 Tau:0.73 ...}
body, _ := api.Encode(img, api.Options{Format: "pgm", Levels: 16, AutoDither: true})
// 也支持显式强度：
body, _ = api.Encode(img, api.Options{Format: "pgm", Levels: 16, Dither: 55})
```

```
gtk encode --format bmp --in a.pgm --out a.bmp --levels 16 --auto-dither
gtk encode --format pgm --in a.pgm --out a.pgm --levels 4 --dither 50
```

`--auto-dither` 与 `--dither` 互斥；未给 `--levels` 时两者都拒绝，避免在无量化
的情况下悄悄改变产物。编码后会打印 `banding/noise/weighted` 三项，便于对照上表。
