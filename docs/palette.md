# 中位切分调色板

给灰度图补的可选量化路径。它只改像素值，不产生新容器、也不改任何格式的文件头：
量化后的像素照旧交给 `EncodePGM` / `EncodeBMP` / `EncodeRLE`。

## 公开参数（`api.Options`）

| 字段 | 类型 | 缺省 | 含义 |
|---|---|---|---|
| `Palette` | `bool` | `false` | 调色板开关。关闭时像素直通，三种格式与 `testdata/golden` 逐字节一致。 |
| `Buckets` | `int` | `0` | 桶数上限 K，仅 `Palette=true` 时生效，取值 `[1,256]`；0 或越界报错。 |
| `VarianceThreshold` | `float64` | `0` | 桶内方差停止阈值 τ 的覆盖值。0 表示按 K 自动推导；正值必须落在 `(0,16256.25]`。 |

三个字段都能从命令行设进去（`--palette --buckets K [--variance-threshold T]`），
不是测试私有开关。`api.PaletteThreshold(K)` 与 `api.QuantizePalette` 也公开，供外部复算。

## 切分维的选择理由

单独写这一节，因为灰度图的通道数为 1，切分维恒为 0——但这恰恰是需要说清的地方：
换成多通道时，规则必须能唯一确定用哪一维切。

规则：每轮在当前所有可切桶里，沿**桶内各通道总体方差最大**的那一维切；并列取最小通道号。
`palette.AxisOf` 就是这条规则，`Bucket.Axis` 等于 `AxisOf(Bucket.Variance)`，
所以任何一次切分用哪一维都能从桶的方差数组直接复算，不需要信实现。

理由：

1. 方差越大意味着该维上像素铺得越开，一刀下去能削掉的平方误差越多，误差下降最快。
2. 灰度只有一个通道，argmax 恒为 0，因此单通道情形不会出现维度歧义，也不会引入空分支。
3. 并列取最小通道号让结果与遍历顺序无关，同一输入两次运行逐像素一致（有测试）。

推导链条：像素 → 每桶每通道方差 → argmax 得切分维 → 该维上按中位值切两半。
这是可逐步复算的，不涉及任何隐含状态。

## 桶内方差阈值的取法

τ 默认由桶数 K 推出，公式

```
τ(K) = Δ² / 12 ,   Δ = 256 / K
```

推导：

1. 理想 K 级均匀标量量化器把 8 位值域 `[0,255]` 划成 K 个等宽格，格宽 `Δ = 256/K`。
2. 在该格里量化误差均匀分布在 `[-Δ/2, Δ/2]`，方差（均方误差）为 `Δ²/12`。
3. 取 τ(K)=Δ²/12 作为停止判据：当待切桶里最大的桶内方差已 ≤ τ，说明它和理想 K 级
   量化的单个格一样紧，再切不会比理想 K 级量化更好，于是停止。

所以 τ 完全由公开参数 K 与 8 位值域决定，没有魔数、没有留空：

| K | Δ=256/K | τ=Δ²/12 |
|---:|---:|---:|
| 4 | 64 | 341.3333 |
| 8 | 32 | 85.3333 |
| 16 | 16 | 21.3333 |
| 32 | 8 | 5.3333 |
| 64 | 4 | 1.3333 |
| 256 | 1 | 0.0833 |

手动覆盖：`VarianceThreshold>0` 时直接用该值，但必须落在 `(0,16256.25]`。
上界 16256.25 是 8 位单通道总体方差的理论最大（分布 p 在 0、1−p 在 255 时
`p(1−p)·255²`，p=1/2 取到 `255²/4`）。负值、NaN、Inf、或超过上界都按“阈值倒置”拒绝。

## 终止条件与算法

循环直到以下任一成立：

- 桶数达到 K（`Stop=bucket-cap`）；
- 最大桶内方差 ≤ τ（`Stop=threshold`）；
- 没有可切桶，即每个桶内样本全同（`Stop=no-splittable`）。

每轮选方差最大的可切桶，沿其切分维按下中位值切；切点挪到第一个严格大于中位值处，
若中位值恰为区间最大值则退到第一个大于等于它处，保证左右两桶非空。像素索引只排序一次，
子桶是排序数组的连续区间，故结果确定、与运行环境无关。

调色板项取桶内均值四舍五入；每个像素映射到自己所在桶的调色板项，因此输出像素必然取自调色板。

## 与灰度直通的均方误差上界

灰度直通（`Palette=false`）是逐字节无损的，所以“调色板解码结果 vs 直通解码结果”的
均方误差就是量化像素与原图像素之间的均方误差。

设桶 b 的精确均值 `m_b`、调色板项 `p_b=round(m_b)`、桶内方差 `σ_b²`、像素数 `n_b`，总像素 N，则

```
(1/n_b) Σ_{i∈b} (v_i - p_b)²
  = (1/n_b) Σ (v_i - m_b)² + (m_b - p_b)²
  = σ_b² + (m_b - p_b)²
  ≤ σ_b² + 1/4                （因为 |m_b - p_b| ≤ 1/2）
```

按像素数加权并对所有桶求和：

```
MSE ≤ W + 1/4 ,    W = (1/N) Σ_b n_b σ_b²
```

`W` 就是“假设每桶都映射到精确均值”的均方误差，可由量化统计直接算出，
所以 `W+1/4` 是一个可计算、对每个输入都成立的紧上界（实现里 `PaletteStats.MSEBound`）。

只用参数的上界：`σ_b² ≤ 255²/4 = 16256.25`，故恒有 `MSE ≤ 16256.5`；
若因阈值停止，则每个 `σ_b² ≤ τ`，于是 `MSE ≤ τ + 1/4`（实现里 `PaletteStats.ParamBound`）。

## 验收对照

- 参数：`Bucket`/`VarianceThreshold`/`Palette` 都在 `api.Options`，CLI 可设（见 `cli-run.log`）。
- 两条子命令：`encode` 与 `decode` 对三种格式、两档桶数各跑一遍，输出在 `artifacts/palette/cli-run.log`。
- 三格式逐一比对：`artifacts/palette/verify.txt` 用独立 Python 解析器（不 import Go 代码）
  比对 `pgm == bmp == rle` 的解码像素，并给出各自 MSE 与文件哈希。
- 只读：`ref/` 与 `testdata/golden/` 的 sha256 在改动前后一致（见 `artifacts/palette/readonly.txt`）。

## 开关关闭时的字节不变性

`Palette=false`（缺省）时，`Encode` 不做量化，`Buckets`/`VarianceThreshold` 保持零值合法，
三种格式与 `testdata/golden` 逐字节一致，头长度与内容都不变。
`Palette=true` 时头同样不变：PGM 的 `P5\nW H\n255\n`、BMP 的前 54 字节、RLE 的前 8 字节都与
关闭时相同，只有像素负载变化（RLE 的游程数会随像素内容变，但头里的宽高是原图尺寸）。

## 错误

| 条件 | 返回 |
|---|---|
| `Palette=true` 且 `Buckets` 为 0、负数或 >256 | `ErrBadPaletteBuckets`（`调色板桶数非法`） |
| `Palette=true` 且 `VarianceThreshold` 为负、NaN、Inf 或 >16256.25 | `ErrBadPaletteThreshold`（`调色板方差阈值倒置`） |
| `Palette=false` 但 `VarianceThreshold` 为负/非有限 | `ErrBadPaletteThreshold` |
| 空像素送入量化 | 错误 |

桶数 0 与阈值倒置在 `Encode`、`Decode`、`QuantizePalette` 三个入口都会拦下；
`Decode` 不做反量化（量化不可逆），只校验参数。
