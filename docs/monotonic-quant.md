# 量化重建的单调性修复：量化区间与重建电平必须同时单调

现象：灰度图经低比特量化（压缩）再重建后强度不再单调——渐变上较暗的点反而被重建得比较亮的点更亮。本文给出重建保持单调所需的两条量化约束、修前样例的实测坏点、修法与逐点实测结果。所有数字由 `go run ./cmd/monoreport` 实际跑出，并由 `internal/quant` 与 `api` 下的测试锁定。

## 1. 单调重建的条件

8 位灰度定义域 `x ∈ {0,…,255}`。`b` 位量化有 `L=2^b` 个码字，量化表由两部分组成：

- `L+1` 个区间边界 `t_0,…,t_L`，第 `j` 个量化区间 `I_j = [t_j, t_{j+1})`（整数点）；
- `L` 个重建电平 `r_0,…,r_{L-1}`，码字 `c(x)=j` 时重建 `Q(x)=r_j`。

要让 `x ≤ y ⇒ Q(x) ≤ Q(y)`，需要且只需要整条复合链不减。把它拆开，充分条件（也是按区间/电平表述时的标准约束）是两半都单调：

1. **量化区间单调（边界严格递增、按输入顺序排列）**

   ```
   0 = t_0 < t_1 < … < t_L = 256
   ```

   从而码字 `c(x)` 随 `x` 单调不减（区间不重叠、不倒序）。

2. **重建电平单调（随码号不减）**

   ```
   0 ≤ r_0 ≤ r_1 ≤ … ≤ r_{L-1} ≤ 255
   ```

   有用的量化器一般取严格递增 `r_j < r_{j+1}`（相等只产生冗余码字，不破坏单调）。

两条同时成立时：`x<y ⇒ c(x)≤c(y) ⇒ r_{c(x)}≤r_{c(y)} = Q(y)`，证毕。
反过来，任意一半被破坏都可能让复合结果向下跳变：区间倒序会让码字回退；
电平表乱序会让“更大的码字对应更暗的电平”。`Table.Check()` 对这两条逐一做量化校验。

## 2. 修后的量化器（按约束构造）

取三档位深 **b = 2 / 3 / 4 bit**（`L = 4 / 8 / 16` 个电平），均匀量化步长 `Δ = 256/L`：

```
t_j = j·Δ                         （j=0..L，末边界 256）
r_j = j·Δ + Δ/2                   （箱内中点；相邻电平差恒为 Δ > 0）
c(x) = min(⌊x/Δ⌋, L−1)
```

三档的量化区间与重建电平（全部满足上面两条单调约束）：

| b | L | Δ | 边界 t | 重建电平 r |
|---|---|---|--------|-----------|
| 2 | 4 | 64 | 0,64,128,192,256 | 32,96,160,224 |
| 3 | 8 | 32 | 0,32,…,256 | 16,48,80,112,144,176,208,240 |
| 4 | 16 | 16 | 0,16,…,256 | 8,24,40,…,232,248 |

实现：`internal/quant/quant.go` 的 `quant.New(bits)`；公共入口 `api.Options{Bits: b}`
在编码前逐像素量化，`Bits=0`（默认）完全不量化，golden 字节不变。

## 3. 修之前坏在哪（留档的非单调样例）

修前量化器的**区间表仍是上面那张单调均匀表**，但重建电平表被按码号做了 `b` 位
**位反转重排**（典型的收发位序 / 电平表索引事故）：

```
r_bad[c] = r_fixed[ bitreverse_b(c) ]
```

区间约束没坏，第 2 条“重建电平随码号单调”被破坏。位反转排列 `p[c]=bitreverse_b(c)`：

- b=2：`p = [0,2,1,3]`，出现 1 次下降 `2>1`；
- b=3：`p = [0,4,2,6,1,5,3,7]`，出现 3 次下降，最大落差 `6→1`（−5 个码号）；
- b=4：`p = [0,8,4,12,2,10,6,14,1,9,5,13,3,11,7,15]`，出现 7 次下降，
  最大落差 `14→1`（−13 个码号，乘上 Δ=16 即 −208 灰度级）。

留档样例（4-bit，256×16 PGM，可直接查看/解码）：

- **非单调样例：`testdata/monotonic/before-bitreverse-b4.pgm`**
- 修后对照：`testdata/monotonic/after-monotone-b4.pgm`
- 原始黑到白渐变：`testdata/monotonic/gradient-src.pgm`

样例上最严重的一对：`x=127 → x=128`（输入只亮 1），重建却是
**232 → 24**——左边较暗的点被重建得接近纯白，右边较亮的点反而接近纯黑，
相邻差 Δ = **−208**。这就是“暗的比亮的还亮”。

修前三档实测（同一全渐变、逐点比较；负号表示向下反转）：

| 位深 | 破坏点数 | 最大反转量 min Δ_i（相邻差，向下为负） |
|------|---------:|---------------------------------------:|
| 2 bit（4 电平） | 1 | −64 |
| 3 bit（8 电平） | 3 | −160 |
| 4 bit（16 电平） | 7 | −208 |

即三档最严重反转的**向下幅度绝对值**分别为 64 / 160 / 208 级。

这些数字由 `TestLegacyBugPreserved` 锁定，留档 PGM 由
`TestPreservedBeforeSampleIsNonMonotone` 校验为“确实有 7 个破坏点、−208”，
防止样例与说明不一致。修前逻辑以 `quant.NewLegacyBitReversed` 原样保留，仅供对照。

## 4. 修后逐点实测：三档破坏点数全为 0

检查方法（不抽样）：取整条 `x=0..255` 黑到白渐变——这正是 8 位输入的**整个
定义域**，256 点一个不缺；对重建序列 `y` 逐对比较全部 **255 对**相邻点。

```
Δ_i = y[i+1] − y[i] ,  i = 0..254      // 题目指定定义；向右为正，向下为负
破坏点数   = #{ i : Δ_i < 0 }
最大反转量 = min_i Δ_i                  // 最负的相邻差；0 表示无向下反转
```

修后实测（`go run ./cmd/monoreport` 原表；也走 `api.Encode→Decode` 的
PGM/BMP/RLE 全管线由 `TestBitsGradientMonotoneRoundTrip` 复核）：

| 位深 | 破坏点数 | 最大反转量 |
|------|---------:|-----------:|
| 2 bit | **0** | **0** |
| 3 bit | **0** | **0** |
| 4 bit | **0** | **0** |

粗量化时同一电平覆盖连续多个输入点，段内 Δ_i=0，因此最负相邻差恰为 0；
没有任何 Δ_i<0，单调性逐点成立。

附：1..8 bit 全位深扫描，破坏点同样全为 0（8-bit 时 Δ=1 退化为恒等，`min Δ_i=+1`）：

| 位深 | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 |
|------|--:|--:|--:|--:|--:|--:|--:|--:|
| 破坏点数 | 0 | 0 | 0 | 0 | 0 | 0 | 0 | 0 |
| 最大反转量 | 0 | 0 | 0 | 0 | 0 | 0 | 0 | +1 |

## 5. 复现

```sh
go test ./...                                   # 含单调性、留档样例、golden 全部测试
go run ./cmd/monoreport                         # 打印修前/修后实测表
go run ./cmd/monoreport -write-samples          # 重新生成 testdata/monotonic/*.pgm

# 端到端：把渐变量化到 4bit 并压成 RLE，再解回 PGM
./build/gtk encode --format rle --bits 4 --in testdata/monotonic/gradient-src.pgm --out /tmp/gtr.rle
./build/gtk decode --format rle --in /tmp/gtr.rle --out /tmp/gtr.pgm
```
